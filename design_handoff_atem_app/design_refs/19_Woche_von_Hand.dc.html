ATEM HYBRID · MODUL 19 · WOCHENPLANUNG 2 VON 3

Die Woche von Hand — sieben Tage untereinander, und ein Heute, das nur abgeleitet wird

Die Planungsseite ist das Werkzeug, mit dem jemand seine übliche Woche selbst festlegt: welche Art an welchem Wochentag, auf Wunsch mit einem seiner Pläne. Das Widget im Hybrid-Tab beantwortet daraus „Was wird heute trainiert?" — für Kraft und Cardio, aus derselben Ableitung, die auch der Kraft-Tab liest. Die App schlägt hier nichts vor, füllt nichts vor und kommentiert keine Menge.

LEITSATZ
Die Woche ist ein Vorhaben in Wochentagen, das jemand selbst hinschreibt. „Heute" wird daraus gelesen, nie angelegt; was geplant und nicht trainiert ist, sieht aus wie jeder andere Tag; und eine Lücke ist keine Aussage — nur „Frei" ist eine.
Drei Folgen. Erste: Plan und Ist werden nie abgeglichen, nur nebeneinander gestellt — kein Häkchen am Eintrag, keine Ampel am Tag. Zweite: eine Ableitung, todayPlan(datum), speist Hybrid-Widget und Kraft-Tab; der Kraft-Tab filtert nur. Dritte: das Briefing ist Bezug, nie Vorlage — was dort steht, steht oben als Zeile, nicht als Eintrag in der Woche.
A · PLANUNGSSEITE, WIDGET UND KRAFT-TAB — EIN DATENSTAND, LIVE
Artboards 1 : 1 in dp bei 360 dp. A1 ist bedienbar: Plus am Tag legt an, Eintrag antippen verschiebt, ändert oder entfernt; Rückgängig steht 6 s. A2 und A3 lesen denselben Stand — ändere Mittwoch und sieh beide mitgehen. „Mitternacht" schaltet den Tag weiter. Tweaks: Startzustand, Speicherfehler simulieren, Animationen reduzieren.

DIE ABLEITUNG · EIN ORT IM CODE (lib/planning/today_plan.dart)
todayPlan(date) →
  wk     = goal.weekPattern == 'alternating'
             ? (weeksBetween(goal.anchorWeekStart, date).isEven ? week.a : week.b)
             : week.a
  rhythm = wk.entries.where(weekday == date.isoWeekday)
             .sortBy(daypart: morning → midday → evening → ohne, dann order)
  appt   = schedule.where(day == date)                      // Bestand, nur Kraft
  items  = appt.isEmpty
             ? rhythm
             : rhythm.where(kind == 'cardio') + appt        // Termin schlägt Rhythmus je Spur; „Frei" fällt weg
  jedes Element: { kind, title, meta, source: 'week' | 'appointment', planResolved }

Hybrid-Widget   = items                                     // alles
Kraft-Startblock = items.where(kind == 'strength').first    // nur Kraft; fehlt → „Zuletzt" (Board 17)

L · VORSCHLAG FÜR DIE FELDER VON planning/week
userProfiles/{uid}/planning/week · ABZUGLEICHEN MIT 04-firestore-schema.md
week {
  a            { entries: { <id>: Entry } }       immer vorhanden
  b?           { entries: { <id>: Entry } }       nur wenn goal.weekPattern
                                                   = 'alternating' je galt
  updatedAt    timestamp                         für „Zuletzt geändert"
}

Entry {
  weekday      1–7                               ISO, Montag = 1
  kind         'strength' | 'cardio' | 'off'
  planId?      string                            nur strength · fehlt = ohne Plan
  planName?    string                            Schnappschuss, wenn planId
  activity     'run' | 'ride' | 'swim' |         nur cardio · Pflicht
               'row' | 'hike' | 'other'
  durationMin? 10–240                            nur cardio
  daypart?     'morning' | 'midday' | 'evening'  nicht bei off
  order        number                            innerhalb Tag + Tageszeit
  createdAt    timestamp
  origin?      reserviert für Board 20           heute nie geschrieben
}
SECHS SCHREIBREGELN
1 · Map statt Array. Jede Handlung ist ein Feld-Update: Verschieben schreibt a.entries.<id>.weekday, sonst nichts. Optimistisch; eine Ablehnung setzt genau dieses Feld zurück.
2 · Kein Datum, kein Heute. Das Dokument kennt nur Wochentage. „Heute" ist todayPlan() und wird nie gespeichert — es gibt keine vorab angelegten Termine.
3 · off ist exklusiv. Ein Tag hat entweder genau ein off oder beliebig viele Trainings. Training auf einen freien Tag löscht das off im selben Batch (Snackbar nennt es).
4 · Plan löschen schreibt nichts hierher. Aufgelöst wird beim Lesen: unbekannte planId → freies Krafttraining + planName. Ändern setzt planId neu und löscht den Schnappschuss.
5 · Woche leeren = entries: {} der sichtbaren Woche, ein Vorgang, ohne Rückgängig. b bleibt bestehen, wenn das Briefing zurück auf „jede Woche gleich" geht — dann gilt es nur nicht.
6 · Keine Kopie des Briefings. Kein Feld hier wiederholt perWeek, days oder dayparts aus planning/goal. Der Anker für A/B wird gelesen, nie gespiegelt.
